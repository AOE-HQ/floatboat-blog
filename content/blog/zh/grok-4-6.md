Grok 4.6 是 xAI 在 2026 年 8 月推出的编程、Agent 任务与知识工作模型。它的核心规格至今仍有竞争力：50 万 token 上下文窗口、文本和图像输入、可调推理力度，API 起步价为每百万输入 token 2 美元、每百万输出 token 6 美元。

不过，Grok 4.7 已在 9 月发布。现在评估 Grok 4.6，重点不再是复述发布时有多强，而是弄清它的真实能力、成本边界，以及哪些情况下仍有保留价值。

**信息核对截至 2026 年 10 月 13 日。**文中所称当前型号、价格与文档状态均以该日期为准。

## Grok 4.6 核心参数

|---|---|

| 发布时间 | 2026 年 8 月 12 日 |

## Grok 4.6 相比 4.5 改了什么

xAI 将 Grok 4.6 描述为 Grok 4.5 的延续，而不是新一代基础模型。根据[官方发布公告](https://x.ai/news/grok-4-6)，xAI 延长了补充训练，重新生成了覆盖不同推理档位和 Agent 框架的监督微调轨迹，并在编程、知识工作、网页开发等环境里进行强化学习。

因此，这次升级的重点不在单轮问答，而在长链路任务：先研究，再执行、检查和修改，尽量保持目标不漂移。xAI 还强调了交互式项目和视觉项目的首版质量。这里应区分事实与口径：训练方式和产品定位来自官方，具体工作流能否受益，仍需用自己的任务验证。

Grok 4.6 首发进入 Cursor 与 Grok Build，随后开放 xAI API，并陆续接入 GitHub Copilot、云平台和模型路由服务。产品宣布接入不代表所有账号都会自动看到它，企业管理员的模型设置仍可能限制实际可用范围。

如果你评估的是整套 xAI 接入，而不只是 4.6 这一个版本，可以结合我们的[Grok API 个人与小团队使用指南](/zh/blog/grok-3-api-solo-operator)，进一步核对搜索能力、供应商集成与生产控制。

## 50 万上下文背后的 20 万计费分界线

50 万 token 能容纳大型代码仓、成组文档或较长的 Agent 历史，但不意味着把窗口塞满就是最优方案。

xAI 在 20 万提示词 token 处设置了计费分界。低于该值时，每百万 token 的标准费率是输入 2 美元、缓存输入 0.50 美元、输出 6 美元；达到或超过 20 万时，则变为输入 4 美元、缓存输入 1 美元、输出 12 美元。[官方价格说明](https://docs.x.ai/developers/pricing)明确指出，一旦越过阈值，整次请求的所有 token 都按长上下文费率计费，并非只对超出部分加价。

这意味着，19.9 万与 20.1 万 token 的请求内容可能几乎相同，费用结构却会明显变化。长时 Agent 应让常用指令和重复材料保持稳定，争取命中缓存；用检索或上下文压缩替代无限追加工具结果；并实测更多上下文是否真的提高成品质量。

`low`、`medium`、`high`、`xhigh` 四档推理力度也会影响成本与等待时间。提取和分类通常不需要与复杂调试、长链规划相同的档位。与其所有任务都开最高档，不如按任务难度路由，再用结果质量决定是否升级。

## 基准数据应该怎么读

xAI 的发布表列出：Artificial Analysis Intelligence Index 61 分、GDPval-AA v2 Elo 1753、CursorBench v3.2 69.9%、DeepSWE v1.1 65.9%、Terminal-Bench v3.0 26%，以及 AA-Briefcase Elo 1577。xAI 同时注明，对手模型数据取自各厂商公开结果或基准榜单。

Artificial Analysis 的[独立分析](https://artificialanalysis.ai/articles/grok-4-6-benchmarks-and-analysis/)同样给出 61 分的综合指数，并认为 Grok 4.6 在 Agent 化知识工作上表现突出。该机构还公布了 Terminal-Bench v2.1 的 88.4%。

26% 与 88.4% 并不矛盾：它们分别来自 Terminal-Bench v3.0 与 v2.1。不同版本的任务集和难度不能放在同一张排行里直接比较。凡是持续更新的基准，都要同时核对版本、推理配置、工具环境和评分方式。

较稳妥的结论是：Grok 4.6 在发布时展现了较强的多步知识工作能力，编程 Agent 评测也有竞争力，且起步价格相对较低。这足以让它进入测试名单，却不足以证明它会在你的代码库、资料库或工具链中自动胜出。

如果价格和部署控制比 xAI 生态更重要，可以再看我们的[DeepSeek V4 Pro 分析](/zh/blog/deepseek-v4-pro-0813)，但不要把两个厂商的自报基准当成完全同口径的数据。

## 它更适合哪些任务，又有哪些边界

Grok 4.6 更适合把推理和持续工具调用结合起来的工作，例如跨多份来源调研后形成报告、阅读代码库并多轮验证修改、分析大量文档或图片、制作需要反复完善的交互原型，以及在支持函数调用和结构化输出的 Agent 框架中执行任务。

选择它的理由不应只是“窗口大”，而是长上下文、推理档位、工具能力和 Agent 评测的组合。

限制同样明确。Grok 4.6 没有开放权重，无法自行部署。xAI 的[模型文档](https://docs.x.ai/developers/models)还说明，模型本身不会自动获得实时信息；要处理最新事件，必须启用网页搜索或 X 搜索工具。它支持文本和图像输入，但只输出文本，图片、视频和语音生成由其他模型或 API 承担。

## Grok 4.7 发布后，4.6 还有没有必要用

Grok 4.7 于 2026 年 9 月 21 日成为 xAI 更新的编程与知识工作模型。xAI 称其采用新的、更大的基础模型，增强了长时任务与自我检查，并保持与 4.6 相同的起步 token 价格。[Grok 4.7 公告](https://x.ai/news/grok-4-7)列出的多项新评测也高于 4.6。

因此，新项目如果要从 xAI 模型中挑一个起点，通常应先测 Grok 4.7。以下情况仍可能保留 4.6：既有工作流已经完成质量与安全验证；当前平台尚未开放 4.7；需要固定旧版本做回归对照；或者切换模型会触发新的合规、安全或采购审核。

不要默认 `latest` 别名永远保持相同行为。只要工作流依赖稳定输出，就应在供应商允许的范围内固定模型版本，并在迁移前重新跑评测。

## 一套更可靠的测试方法

不要用一道通用提示词决定是否采用 Grok 4.6。选取一组真实任务，其中至少包含常规案例、困难案例和历史上容易失败的案例；评分对象也应是最终成品，而不只是第一条回答。

建议记录六项指标：

1. **完成质量：**是否真正达到验收标准；
2. **工具可靠性：**是否正确选用工具并从失败中恢复；
3. **人工返工量：**结果可用前还需要多少修改；
4. **上下文表现：**增加资料后是提高准确度，还是引入噪声；
5. **总成本：**包括输入、缓存输入、输出、重试和 20 万 token 分界；
6. **端到端耗时：**衡量整项任务，而不是只看首 token 延迟。

如果要与 Grok 4.7 对比，两边必须使用相同的 Agent 框架、工具权限、上下文、推理档位和评分规则。给其中一个模型更多重试或更好的检索，得到的就不是模型对比。

## 结论

Grok 4.6 是 xAI 在 Agent 编程与知识工作方向上的重要版本。它的已确认优势包括 50 万 token 上下文、可调推理力度、图文输入，以及发布时有竞争力的 Agent 评测；标准起步价则是每百万输入 token 2 美元、输出 token 6 美元。

同时也要看到边界：超长提示词会让整次请求进入更高费率，不同版本的基准不能混用，最新信息需要搜索工具，而 Grok 4.7 已成为更新的首选候选。对新项目来说，4.6 不再是默认起点；对已经验证并稳定运行的流程来说，它仍可以作为受控版本继续使用。
