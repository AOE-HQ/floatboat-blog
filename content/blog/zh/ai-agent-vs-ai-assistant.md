AI 助手帮助人完成任务；AI Agent 可以接受一个结果委托，在规定环境中自行选择行动。真正的边界不是聊天界面、模型名称、记忆功能或产品标签，而是：**下一步由谁控制，系统可以行使多大权限。**

本文只负责助手对比，重点是交互方式、触发、工具、权限、状态、监督、风险与评估。更广的 Chatbot、Workflow、Agent 架构分类由独立的 [AI Agent 与 Chatbot 对比指南](/zh/blog/ai-agent-vs-chatbot)维护，避免两篇重复承担同一搜索意图。

## 可以落地的定义

**AI 助手**响应用户，为起草、摘要、解释、建议或操作提案提供支持。人通常决定接下来做什么，并持续担任实际操作者。

**AI Agent**为了完成受托目标，能够自行决定部分过程和工具调用。Anthropic 把 Agent 定义为由模型动态控制过程与工具使用的系统，并与代码路径预先规定的 Workflow 区分。NIST 当前的 [Agentic AI 工作](https://www.nist.gov/agentic-ai)同样强调自主行动以及与外部系统的交互。

微软当前的 [Copilot 与 Agent 说明](https://www.microsoft.com/en-us/microsoft-copilot/copilot-101/copilot-ai-agents)也展示了两者可以共存：助手可以成为人调用专业 Agent 的界面。因此，“助手”和“Agent”可能描述同一个产品的不同层。

## 真正有用的对比

| 维度 | AI 助手 | AI Agent |
|---|---|---|
| 主要关系 | 人在工作中使用 AI | 人委托一个有边界的结果 |
| 触发方式 | 通常由用户直接请求 | 用户、事件、日程或系统状态 |
| 下一步 | 通常由用户请求或确认 | 模型可以在政策内选择 |
| 工具使用 | 常由用户发起或先预览 | 可以在执行循环中反复选择 |
| 权限 | 常见为读取、分析或草拟 | 可能包含受限写入和外部行动 |
| 状态 | 对话与当前成果 | 运行阶段、检查点、审批、工具结果和外部 ID |
| 人工监督 | 逐次交互、持续参与 | 检查点、异常、审批和监控 |
| 主要风险 | 人采纳错误建议或内容 | 错误连锁放大或产生越权副作用 |
| 评估 | 回复质量与人的实际收益 | 结果、完整轨迹与环境变化 |

这些是行为倾向，不是法律分类。强大的助手也可以使用工具和记忆；受严格控制的 Agent 也可能频繁请求批准。应评估行为与权限，不要只看品牌名称。

## 触发：谁开始工作？

助手通常等待人打开界面并提出请求。它可以建议回复或主动展示资料，但用户仍在每次交互中。

Agent 也可以由用户启动，还可能响应事件、日程、队列任务、文件变化或应用状态。自动触发本身不构成 Agent：按时运行的固定流程仍然是 Workflow；模型在运行中选择下一步，才是 Agent 部分。

评估产品时应追问：什么能启动运行？能否按账户、事件类型或数据类别限制？重复事件会不会造成重复行动？能否全局暂停新任务？触发器与政策版本是否进入记录？

## 工具：有连接器不等于有 Agent 能力

助手和 Agent 都能调用工具。助手可以在人注视下搜索文件、计算或创建邮件草稿；Agent 则可能依次搜索多个来源、判断证据缺口、调用其他工具、更新记录，并持续执行到任务契约满足。

真正应核对的是：工具由模型还是应用代码选择？调用只是建议、草稿还是立即改变外部状态？系统能否根据结果继续调用其他工具？输入是否经过结构校验，输出是否作为不可信数据处理？每次写入是否幂等且可追踪？

NIST 的 [Agent 工具使用研究](https://www.nist.gov/news-events/news/2025/08/lessons-learned-consortium-tool-use-agent-systems)把自主性描述为系统在无人干预时使用工具的主动性与自由裁量程度。因此，工具权限是一条连续光谱，不是有或没有的开关。

## 权限：最清晰的实践边界

只读取指定文档并产出草稿的助手，运行影响范围很小。能够发送、发布、付款、删除或修改访问权的 Agent，即使使用相同模型，影响范围也完全不同。

| 行动层级 | 例子 | 合适的默认控制 |
|---|---|---|
| 读取 | 搜索授权文档 | 助手或采用最小权限的 Agent |
| 草稿 | 准备邮件、报告或变更提案 | 助手；必须复核的 Agent |
| 可逆写入 | 添加标签、创建测试记录 | 窄身份、日志和回滚 |
| 高影响写入 | 对外发送、发布、付款、删除、授权 | 明确知情审批和强控制 |

授权必须由应用或工具网关执行，不能问模型“你是否有权”。审批界面应展示准确目标、参数、依据与预期影响。

## 状态和记忆不是品类定义

“助手只有会话记忆，Agent 必然有长期记忆”的旧说法并不准确。现代助手可以使用保存偏好、聊天历史、项目、文件和连接来源；如果开发者没有加入存储，Agent 在两次运行之间也可能完全无状态。

应区分：

- **上下文：**当前一次决定能看到的信息。
- **记忆：**准备在未来使用的选定事实或偏好。
- **运行状态：**任务阶段、已完成步骤、审批、重试、检查点与外部副作用 ID。

助手可能需要上下文和记忆来改善个性化；Agent 在暂停、恢复、重试或改变外部系统时，则必须有可靠运行状态。对话文字本身不能替代状态。

若要定位跨会话连续性问题，可参考[为什么 AI 会在会话之间遗忘](/zh/blog/why-ai-forgets-between-sessions)。

## 监督：持续互动与控制点

助手通常由人持续监督：提出问题、阅读、修改，再决定下一条指令。对于模糊且依赖判断的工作，这种方式很有效，因为系统采取下一步之前就能被纠正。

Agent 的监督应围绕控制点设计：高影响工具前审批；证据不足时暂停；政策冲突或权限失败时升级；限制轮数、时长、成本和工具调用；异常进入复核队列；提供停止新任务的总开关；获得人工输入后能够恢复。

如果人只看到一个笼统的“批准”按钮，或者不可逆行动完成后才收到通知，就不是真正的人在环中。

## 输出变成行动后，风险会变化

错误的助手回答可能误导用户、在草稿中泄露信息或产生差分析。人工复核提供了拦截机会，但流畅表达仍可能让人过度信任。

Agent 还会增加系统风险：错误计划触发一串工具调用；不可信文档通过提示注入影响行动；宽泛凭证扩大影响；重试制造重复副作用；陈旧状态执行过期决定；长循环放大费用和错误；无人值守操作跨越组织边界。

自主性越高，对身份、权限、沙箱、日志、评估、检查点和恢复的要求越高。仅靠“写好提示词”无法解决这些问题。

## 任务适配：辅助还是委托？

以下情况优先选择助手：人必须互动塑造成果；任务是一次性分析、草拟、解释或决策支持；模糊点需要通过对话澄清；每个高影响步骤都应由人决定；产出可复核成果已经足够。

如果这个助手会通过个人账号处理工作资料，应先阅读[个人 AI 助手用于工作的边界指南](/zh/blog/ai-assistant-for-personal-use-at-work)，核对数据分级、雇主政策与账号边界，再选择产品。

以下情况才考虑 Agent：结果可以测试；路径变化大到固定流程难以表达；推进任务需要反复读取环境反馈；工具和权限能够收窄；停止、升级和恢复条件明确；价值足以覆盖额外延迟、成本与运行风险。

步骤已知而且应稳定执行时，使用 Workflow，不必强行贴上任一标签。Anthropic 的[有效 Agent 指南](https://www.anthropic.com/engineering/building-effective-agents)建议只有简单方案无法满足时才增加复杂度。

## 同一项任务可以同时使用两者

以准备并发送客户续约方案为例。

助手层帮助人检查账户历史、比较条款、起草方案并修改措辞；Agent 层可以收集已授权记录、校验必填项、创建版本化草稿、请求批准，并且只在获得授权后保存和发送。

交接必须写清：已接受的草稿与证据、目标客户和允许渠道、政策与模板版本、审批人和有效期、幂等键，以及确认与失败路径。

助手不是“低级产品”，而是需要判断时的正确界面；Agent 也不是“更聪明”，而是承担更大控制责任的委托执行层。

## 助手和 Agent 应采用不同评估

### 助手评估

用代表性请求检查事实、相关性、来源、指令遵循、清晰度、编辑成本、不安全建议，以及用户能否识别不确定性。衡量助手是否提高了人最终接受的成果，而不是用户是否喜欢它的文风。

### Agent 评估

同时检查结果与完整轨迹。Anthropic 当前的 [Agent 评估指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)建议针对实际任务组合代码、模型和人工评分。

衡量工具选择和参数、证据、状态变化、政策违规、审批、干预、重复副作用、恢复、延迟，以及每个可接受结果的成本。案例应覆盖正常、边界、对抗和中断情形。

### 公平比较

给两种系统同样的来源和预期成果。助手由人配合操作；Agent 只能使用已声明工具和审批。比较可接受成果质量、人工时间与修正量、越权尝试、缺数据或工具故障后的恢复、完整成本和耗时，以及第二位运维人员能否解释发生了什么。

只有减少互动产生的价值足以覆盖额外控制面时，Agent 才真正胜出。

## 产品无论自称什么，都应追问这些问题

1. 什么启动工作，谁决定下一步？
2. 哪些工具无需确认即可调用？
3. 使用谁的身份与权限？
4. 哪些状态会保存，存在哪里，保留多久？
5. 哪些行动需要审批，审批人能看到什么？
6. 来源数据与不可信指令如何隔离？
7. 运行能否安全暂停、恢复、重试和对账？
8. 能提供哪些轨迹与评估证据？
9. 管理员如何停止运行并撤销访问？

即使营销名称含糊，这些答案也会暴露真实运行方式。

## 结论

需要提升思考与创作，同时保留逐步控制时，用 AI 助手。能够定义成果、收窄权限，并有能力运营一套自行选择和执行中间动作的系统时，再用 AI Agent。

许多实用产品会把两者结合：助手是协作前台，Agent 在后台处理有边界的任务。真正的问题不是哪个标签更先进，而是判断在哪里结束、委托从哪里开始，以及控制必须在何处变得明确。
