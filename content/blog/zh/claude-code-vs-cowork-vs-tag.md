**TL;DR**
  * **Claude Code vs Cowork vs Tag**的分野在产品形态，不在模型质量：Code 是面向一名工程师与一个代码仓库的本地编程 agent；Cowork 是面向一个人与其文件的本地知识工作 agent；Tag 是住在 Slack 频道里的共享异步 Agent 同事。

  * Code 和 Cowork 站在同一级台阶上——陪你运行约一小时工作量级的单用户本地 agent。Tag 在下一级：多人协作、主动执行、长周期，记忆比一次会话活得更久。

  * 诚实的产品形态跟随**任务时长**。分钟级归聊天。约一小时归本地 agent（仓库用 Code，文件用 Cowork）。小时级再加自我排程，才值得养一个异步 Agent 同事。

  * 三个迁移把 Tag 和另外两个分开：单用户到多人、pull 到 push、一次性会话到长跑异步任务。

  * 仓库选 Code，你自己的文件与连接器选 Cowork，已经被一个频道「共同拥有」的工作选 Tag。每个产品的定义都在各自的中心文章里，链接见下文。

## 1\. 产品形态跟随任务时长

Claude Code vs Cowork vs Tag 之间值得问的问题，不是哪个模型更聪明，而是哪种产品形态能匹配「在没有人类介入时模型能连续干多久」。产品形态跟随任务时长。分钟级归聊天——人必须守在循环里，因为模型守不住。约一小时，本地 agent 开始有意义：它能读一个仓库或一组文件、动手处理、交回可复核的结果，但它仍然属于用户身边。只有当模型能连续干数小时、还能自己排定稍后的复检时，异步 Agent 同事才不是一场表演。

Andrej Karpathy 的三阶段草图——聊天、然后是本地编程 agent、再然后是一个 Agent 同事——很容易被误读成营销叙事。它其实是一架能力阶梯。Chat 回答问题；Claude Code 替一个人执行工程工作；Claude Cowork 对一个人的文档与已连接应用做同样的事；2026 年 6 月进入 Slack 的 Claude Tag，则是把第三种形态放进团队本来就在聊天的那个房间的首次主流尝试。同一个模型家族可以为三者供能。但这些形态并不可互换：一旦你离开私人会话，协作、记忆和计费全都会变。

Anthropic 自己的用法是「存在性证明」，不是买家指南。该公司表示，`@Claude` 现在已是其产品组织完成工作的主要方式之一，并引用过一个数字：产品团队内部代码约有**65%**经由一种内部 Tag 式工作流流转。这个数字很容易被过度解读成「Tag 取代了 Code」。并没有。它意味着，原本大量在终端里发起的工作，现在改从频道里发起——因为其他人本来就已经挂在那个频道上了。

## 2\. 给 Claude Code、Cowork 与 Tag 下定义

这三个产品是同一个 agent 循环——规划、工具、长时执行——瞄准三种不同工作。**Claude Code**是本地编程 agent：你启动它，它用你的凭据对着一个仓库干活，会话归你。**Claude Cowork**是同一个本地 agent 循环，瞄准知识工作：Claude 应用里的文件、文件夹与连接器，仍是单用户，仍是用户发起。**Claude Tag**是共享异步 Agent 同事：管理员把一个 Claude 以组织身份放进选定的 Slack 频道，任何人都能 `@Claude` 派活，线程保持可见，同事可以接手或续跑。即使人们关掉 Slack，Tag 也能继续干活——包括排定它自己的后续动作。

这个分野容易看漏，因为 Code 和 Cowork 感觉上很近，而 Tag 在接入 Git 后也能开 pull request。Code 为一名字工程师和一棵文件树优化；Cowork 为一名知识工作者和他的文档优化；Tag 为一个频道优化——那里已经装着论点、缺陷、指标，以及那个将批准改动的人。把模型**放进**那个上下文，才是重点；把一段摘要**粘贴进**模型，是更老的做法。

这张表的中列才是重点。Cowork 不是迈向 Tag 的半级台阶，而是换了作用对象的 Code。两者都本地、都单用户、都由用户发起。Tag 是三者里第一个让工作单元从「我的会话」变成「我们的频道」的。

### 2.1 核心定义

按 Claude Tag 正在测试的含义，**Agent 同事**是住在团队既有协作界面里、共享的长周期 agent：有分舱记忆，能在不重新给提示词的情况下开工或续工。Code 和 Cowork 仍是本地 agent：私密或小范围受众，限于一个仓库或一组文件夹，且设计得让人类可以伸手干预。Agent Identity、频道记忆、Ambient 模式与组织级计量计费，都归各定义中心文章管——what is Claude Code、what is Claude Cowork、what is Claude Tag；本文只讲为什么这三种形态不是彼此替代品。

### 2.2 三个迁移必须同时发生

只有当三个迁移同时发生时，Tag 才把自己和 Code、Cowork 区分开。第一个是**单用户到多人**。Code 和 Cowork 很懂一个用户的仓库或文件，但它们不会坐在事故频道里，看 PM、值守工程师和客户成功负责人一起补充同一个故事。Tag「每频道一个 Claude」的规则让交接变得便宜：下一个人不必重新解释项目，因为线程本身就是提示词。

第二个是**pull 到 push**。Code、Cowork 和桌面委派都在等一个人注意到「有活要干」。而一个同事可以盯一条安静下来的线程、反馈里反复出现的错误、或一条越线的指标，然后自己把活捡起来。这是另一份不同的「委托契约」——也是企业最先拷问的行为，因为一个未经提示就行动的 agent，可以在没有会议的情况下花钱、碰系统。

第三个是**同步轮次到异步长周期工作**。在 Code 和 Cowork 里，有价值的循环往往仍是「它跑的时候我守在旁边」。在 Tag 里，则是「派下去、离开、回来拿结果——或者等到周三的复检」。自我排程把一次长跑变成一条链。没有它，同事只是慢速聊天。

三个里丢掉任何一个，你都退回一个熟悉的旧产品。多人没有异步，是共享问答机器人；异步没有多人，是合上盖子的 Code 或 Cowork；push 没有记忆，是一个聒噪的实习生。Tag 押注的是：这三者如今能在同一副界面里同时成立。

### 2.3 这三个不是什么

Claude Tag 不是加了 Slack 通知的 Claude Code。如果工件是一次 commit、测试都在 CI 里、且只有一名工程师需要追踪，Code 仍是更贴合的工具。Claude Cowork 也不是轻量版 Claude Code——一名重新整理文件夹、做演示稿的顾问，不是把代码发到仓库的工程师；Cowork 的文件与连接器范围正是它的重点，而不是缺陷。把三者混着选，会买出错误的结果：给一个只需要整理文件夹的顾问买个 Team 套餐的 Slack agent，或给一场整个值守轮班都得看见的事故开一个桌面会话。

三者也都不是 Slack AI。Slack AI 帮团队**读懂**工作区（总结、搜索、回顾），而 agent 是跨已连接工具**执行**、再把结果写回线程。很多团队会同时留着 Slack AI 补进度、留一个 agent 干执行。三者也都不是日历驱动型 AI。聊天里的同事等的是频道活动、`@` 提及或 Ambient 规则；日历驱动型 agent 等的是事件与截止日。两者都是主动式的，但运行时不是同一个。那些因为日历挪了而漏掉跟进的人，仍然需要日历当钟表。

## 3\. 异步形态依赖的三个条件

Claude Tag 不是新品类发明。一年多来，一直有产品想让团队像 `@` 一位同事那样 `@` 一个 agent——Devin、OpenClaw，以及一长串从未走出演示频道的 Slack 机器人。大多数都没能留存。同事型体验比同事级模型到货更快：一个假设自己能无人监督干数小时、有稳定记忆、有社交判断力的界面，如果模型仍每隔几分钟就要找一次人，就会腐烂。Anthropic 公开的说法是：只有当模型能撑住长任务、能维护一份「团队在意什么」的档案、能判断什么时候不该说话之后，Tag 才值得拿来自家试用。这三者里若有一个是弱的，诚实的产品就仍是 Code、Cowork 或 Chat。

**长周期自主**是第一个条件，也就是 §1 里的那架阶梯。编程之所以是楔子，是因为仓库给了模型一个封闭世界：文件、测试、diff。公司知识工作要乱得多——要等客户、等仪表盘、等法务复核——所以 agent 必须能暂停再续跑、不掉线。Tag 在单次长跑之上又加了自我排程：今天能做的先做掉，约好下一次唤醒，把一次次运行串成持续数周的项目。同事就是这样才有资格「拥有」一个留存指标，而不是只写一次性脚本——token 消耗也因此变成「凌晨两点这 agent 还上着班」。

**记忆**是第二个条件，而能在团队中存活下来的版本并不光鲜：一个模型可读可写的文件系统，加上硬隔墙，让一个 Claude 无法在公司里乱逛。评估 Tag 式 agent 的人会描述三个可审查的层——当前任务用的**线程上下文**、那个房间稳定规则的**频道记忆**、公共工作区可能复用的**工作区记忆**。法务频道和工程频道应当像两间分开的办公室。提炼能力正是更强的模型拉开差距之处：弱模型记流水账，强模型沉淀打法手册。

**判断力**是第三个条件，而演示总是跳过它。一个不知道何时该插手的同事，要么沉默、要么话痨。Tag 的 Ambient 模式就是这个押注的产品化表达：盯着频道和工具，把重要的浮上来，其余别碰。两种形态都用过的团队常反馈，Tag _更像_一个同事而非 Code——不是因为模型是另一个物种，而是因为产品是为一屋子人调出来的。如果治理上接受不了未经请求的主动行动，就关掉 Ambient。你仍然有多人执行，只是不再有一个自己找活干的同事。

这三个条件也预言了 Tag 最先接走的是哪类活。和 Code、Cowork 相比，它接走的是「协作与原始上下文密集」的工作——公开事故、发布频道、五个人已经讨论过的升级事项——以及必须在某人抽得出时间给提示词之前就得动起来的工作。适配测试很紧凑：好几个人、一团乱的历史、时间压力、脏到没人想要。Anthropic 是最干净的活例，因为那里的文化本来就是频道优先。那是一种预览，而不是给仍在私聊里拍板的公司的一份落地计划。

## 4\. 采用的双重关卡

如果模型已经就绪，下一个问题是这种形态会传播得多快。2026 年初已经预演过一轮。Viktor——一个跑在 Slack 和 Teams 里的第三方 AI 员工——2 月公开上线，到 2026 年 5 月 Accel 领投那轮时，已在约十周内做到**1500 万美元**年化收入、**12000+**工作区安装、数千家组织付费——Slack 的联合创始人也在股东名册上。这条曲线证明「在聊天工具里 `@` 一个员工」是真需求。它不证明所有企业今年都会买。同一品类的从业者通常预测得更慢：这种形态的 product-market fit 在**小型、透明的科技公司**里。要进入主流企业要撞两道关卡，而且两道都得开。

**成本是第一道关卡**，而且比席位价格更大。一家二十人的公司把前沿同事当免费劳动力用，可以一个月烧掉五位数，却什么都没发布。结构性原因在缓存。1:1 会话——Code 或 Cowork——是一条连续线，下一轮可以复用上一段前缀。频道是异步的：一个人 11:00 开工，另一个人午饭后接着干，前缀往往已经不在了。让一个 agent 被权限不同的人共享，再挂一大池工具上去，缓存布局就再也长得不像私人会话了。协作形态的上下文，不像聊天那样可以缓存。

**权限是第二道关卡。**看不见工作的同事就没法干工作。什么都能看见的同事，就是拿着生产凭据的新实习生。按频道划分的身份、由管理员配置的工具，胜过「机器人用的是 Steve 的 OAuth」。它们还算不上一套完成态的身份系统。企业买家谈这件事，就像谈自动驾驶：99% 正确照样过不了采购——因为剩下那 1% 是一次客户数据倾倒、一次发错频道的泄漏、或一次针对系统提示词的越狱。开放文化的小公司能接受这些，多数受监管企业不能。早期试用评论集中在两个抱怨上：它真能用；但我们不敢把它指向整个租户。一句广为流传的话道出了锁定恐惧：Claude Tag 就像把整家公司交给 Anthropic，再按月租回来。

两道关卡解释了为什么这个三选一不该靠演示来决定。Code 和 Cowork 每个有效工时看起来更便宜，因为上下文是连续的、爆炸半径只有一个人。Tag 在作战室里看起来更强，因为上下文已经在那里——所以它才像「人头」实验一样定价与治理，而不是像插件。如果你需要别的形态打包（Teams、本地化归属、先批准后发送、Agent 原生群聊），岗位适配排行在 best Claude Tag alternatives 和 best Claude Cowork alternatives 两篇文章里，那才是采购地图。本节只讲那条约束：形态可以成熟了，而组织还没就位。

## 5\. 下一步：这层界面会走向哪里

一旦 Tag 是同事而不是「Slack 里的 Code」，价值就逐层展开。第一层是一扇**上下文之门**。瓶颈往往不是智能，而是上下文的完整度。旧工作流要一个人把一周压缩进一句提示词；新工作流把模型直接停在原始流里。Slack 是第一扇门，因为那是 Anthropic 本来就在工作的地方，而且公司已经说过，希望 `@Claude` 出现在团队工作的更多场所。

第二层是**数字员工**：记忆、主动性、对一个循环的所有权——读指标、发改动、盯仪表盘、在决策点上 ping 一个人。第三层更接近**公司操作系统**。人类可以分工，却无法合并大脑。会议、文档和周报，都是带宽极低的合并尝试，还会把隐性知识掉在地上。一个能 fork（开许多副本并行探索）又能 merge（把心得写回共享记忆）的同事，改变的是公司的学习速率，而不只是工单吞吐——而正是在这一层，换供应商会像换掉一个部门。

护城河若出现，靠的不是导出的记忆，而是**运行中状态**：正等客户的任务、指标阈值、或一个待处理的 PR。中途更换厂商，意味着要把它承诺过的东西重新教给一个新 agent。聊天时代几乎没有切换成本；同事形态的工具，如果真被用起来了，就会有。一小段质量领先很难变现，除非它粘在一个解不开就痛苦的工作流上。

那层界面的控制权仍在争夺中。模型实验室握着智能与轨迹；协作套件握着房间；记录系统握着对象；独立 agent 网络押注的是：agent 应当是一等参与者，而不是插件。当一方同时拥有模型和 IM，前两者就坍缩了。2026 年的这场仗，打的是谁坐在那条流里。
