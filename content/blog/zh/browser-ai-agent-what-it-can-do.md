**浏览器 AI Agent** 可以读网页、导航、点击、输入、比较信息，有时还能完成受支持的动作。听起来像人使用浏览器，但这不代表每一种网站任务都可靠，也不代表都适合自动化。

真正有用的问题不是“它会不会用浏览器”，而是“它能否在这个浏览器上下文里、使用这些权限完成这项任务，并留下可核验结果”。本文主责能力与任务选择；提示注入与威胁建模则交给单独的[浏览器 AI Agent 安全检查表](/zh/blog/browser-ai-agent-security-questions)。

## 先确认浏览器上下文

“浏览器 Agent”可能运行在不同环境：

- 有独立 Profile 与状态的**内置浏览器**；
- 能使用现有 Chrome、Edge、Brave、Opera 或 Vivaldi 登录态的**浏览器扩展**；
- 在远程计算机运行的**云浏览器**；
- 通过结构化接口读写服务的 **App 或 Plugin**。

这些环境不能互换。OpenAI 当前的 [Browser 指南](https://learn.chatgpt.com/docs/browser)说明，内置浏览器使用独立 Profile，扩展可以操作现有标签页与登录态，云浏览器则与用户设备分离。登录、上传、可用性与控制还会因套餐、灰度和工作区策略而异。

测试前先记录使用的是哪一种表面，否则“我这里能跑”无法复现。

## 浏览器 AI Agent 擅长什么

### 从明确网页集合中读取与抽取

Agent 可以打开指定页面、定位字段、概括文字，并把可见信息整理成表格或简报。信源明确、所需字段已知时最稳定。

好的任务是：“打开这五个产品页，记录公开的套餐名、计费周期与限制，给每条信息附链接，缺失字段标为未说明。”不好的任务是：“研究最好的产品。”后者隐藏了信源、时效、比较标准和停止条件。

### 跨网站比较选项

Agent 可以从多个网站收集同类属性、统一单位，并指出缺失信息。购买、法律、医疗或财务判断仍应留给用户。Agent 应组织证据，而不是暗中改变决策标准。

### 填写表单并准备提交

浏览器 Agent 可以在受支持表单中填写内容，并在高影响提交前暂停。结构化源数据、动作可逆、最终页面可复核时，适合处理重复录入。不要让它猜测缺失的身份或法律声明，也不要提交给不明确的对象。

### 在已登录 Web 应用中工作

使用获准的浏览器 Profile 或登录流程时，Agent 可以读取或操作 SaaS。扩展可使用日常浏览器登录态；云浏览器与内置浏览器则维护独立 Session。OpenAI 的[浏览器扩展指南](https://learn.chatgpt.com/docs/chrome-extension)列出了在 Gmail、Salesforce 和内部工具等网站中工作的方式，但实际访问仍受用户账号与网站权限限制。

有稳定的 App 或 Plugin 时优先使用结构化操作；只有任务确实依赖网页界面，或没有合适集成时，才用视觉浏览器控制。

### 视觉检查网页结果

Agent 可以检查渲染状态、截图并确认表单是否已填、筛选器是否生效、页面是否符合参考图。视觉确认无法证明不可见的后端变化；写入任务还要核对最终记录或系统状态。

## 用任务分级决定自动化程度

| 等级 | 任务形态 | 建议方式 |
|---|---|---|
| 1 | 阅读、搜索、总结 | Agent 可执行，用户核验信源 |
| 2 | 比较与结构化 | Agent 执行，用户复核标准和结果 |
| 3 | 填写或起草，不提交 | 在沙箱/草稿运行，用户检查字段 |
| 4 | 可逆写入 | 窄权限、确认与状态校验 |
| 5 | 高影响或不可逆动作 | Agent 准备证据，人做决定与执行 |

风险不由点击次数决定。一次付款可能比阅读三十页资料更危险。应按权限、可逆性、敏感度和错误代价分级。

## 通常不适合无人执行的任务

遇到以下情况，不应无人自动化：成功标准主观或无法从可见状态验证；需要猜测身份、法律、财务或医疗信息；权限比任务更宽；错误会形成不可逆承诺；网站频繁变化、阻止自动化或使用不支持的 CAPTCHA/登录；多个并发任务可能改同一记录；写入失败后无法判断是否成功。

OpenAI 官方文档明确指出，有些网站会阻止自动浏览器，部分 CAPTCHA 与认证流程也无法完成。“被阻止”应是正常终态，而不是绕过网站的理由。

## 常见失败模式

### 页面变化

标签、布局、弹窗、响应式状态和实验会移动控件，Agent 可能点错或丢失路径。写入前要核对目标页面与可见状态。

### 信息缺失或过时

网页可能省略字段、显示缓存，或出现日期冲突。要求标注“未说明”并引用具体页面，不要推断值。

### Session 没有正确上下文

云浏览器不会自动继承本地标签页、Cookie、扩展、文件和密码；内置 Profile 也不同于日常浏览器。任务必须说明需要哪个上下文与账号。

### 工具或网站中断

登录、CAPTCHA、下载、上传、限流、弹窗和域名封锁都可能阻断任务。预先定义由用户接管、尝试获准替代方案，还是直接停止。

### 重试造成重复写入

Agent 无法确认提交是否成功时，再试一次可能创建重复记录或消息。使用唯一标识，搜索结果记录，并把不确定情况交给人工。

### 页面包含误导指令

网页内容是不可信输入，可能与用户任务冲突。限制网站范围，不提供无关敏感上下文，高影响动作必须确认；更完整的控制见安全专题。

## 一套可复现的浏览器 Agent 实验

不要用个人正式账号和一次成功回忆来评估。建立沙箱、测试账号或可逆草稿流程，并保存：

1. **起始状态：**浏览器表面、账号角色、权限、URL 与测试数据；
2. **任务：**目标、允许网站、禁止动作和停止条件；
3. **预期结果：**字段、引用、草稿状态或要核对的后端记录；
4. **案例：**正常、缺数据、布局变化、网站封锁、Session 过期、值冲突和写入中断；
5. **证据：**截图、最终 URL、信源、工具轨迹和可用的后端状态；
6. **指标：**完成、严重错误、多余动作、人工介入、耗时和恢复结果。

Anthropic 的 [Agent 评估指南](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)建议：修改数据的浏览器任务既要核对可见页面，也要核对后端状态，避免把确认页面误当成交易已经成功。

浏览器、模型、网站、权限或流程变化后，用同一案例集重跑。一次成功是演示，指定案例持续成功才是证据。

## 有边界的浏览器任务模板

> **目标：**[可观察结果]。
>
> **使用：**[指定浏览器/Profile 与获准网站]。
>
> **读取：**[允许页面或记录]。
>
> **禁止：**[网站、数据或动作]。
>
> **在此之前停止：**[提交、付款、删除、发消息或承诺]。
>
> **被阻止时：**[请求接管/返回证据/停止]。
>
> **验证：**[可见字段，以及后端记录或来源链接]。
>
> **返回：**[结果、信源、已执行动作、未解决事项]。

## 先选工具，再选自主程度

只需要公开信息时使用搜索或直接研究；已有稳定结构化连接时使用 App 或 Plugin；需要独立网页 Session 或视觉页面工作时用内置浏览器；需要现有登录 Profile 时用扩展；云浏览器则只在独立 Session、认证能力与可用范围匹配任务时使用。

随后只给完成任务所需的最低权限。从只读或草稿开始，记录修改量，评估集通过后再开放可逆写入。高影响动作始终保留给人决定。

浏览器 AI Agent 最有价值的定位，是受控执行可观察网页工作，而不是获得一句“替我处理整个互联网”的笼统授权。任务、浏览器上下文、权限与验证方式共同决定它是否真正可用。
