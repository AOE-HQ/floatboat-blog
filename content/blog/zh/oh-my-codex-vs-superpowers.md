嗨，我是 Nova。大约六周前，我把整套 AI 编码环境从浏览器标签页换到了终端，最让我意外的不是速度或工作流，而是：我不再对把代码贴进去这件事感到别扭了。

这是没人聊的那部分。当你独自在做什么的时候——一个副业项目、一个小 SaaS、一个你还不确定会不会留着的工具——每次把一段代码库交给聊天窗口，心里都会有一笔无声的账：_我真的希望这段代码、带着这些注释，躺在某个第三方日志里吗？_ 多数日子你还是照贴不误。但你会注意到。

在 **Linux 上跑 Claude Code** 改变了我这笔账。不是因为 AI 从此「离线」了——这点我后面会讲，因为网上的说法有误导——而是因为它改变了**我的工作里有哪些部分会碰到云**，以及我对这条边界有多少掌控。

## Claude Code on Linux 到底带来了什么

先厘清用词。网上关于这件事有太多混乱的说法。

### 终端原生的 AI 开发

Claude Code 是一个 CLI。你在终端里跑 `claude`，把它指向一个项目，它就能读文件、跑命令、改代码、用工具——全部在你现有的开发环境里完成。没有浏览器标签页，没有复制粘贴的往返。按[官方 Claude Code 配置文档](<https://code.claude.com/docs/en/setup>)的说法，它支持 macOS、Linux（Ubuntu 20.04+ / Debian 10+）和 Windows，最低 4GB 内存，以及一条联网连接。

最后这一点——联网——正是这篇文章要讲的关键。

![2.PNG](/blog/images/oh-my-codex-vs-superpowers/1777514558143-410fe505-0889-4148-937c-fc2dfbd3a60b.PNG)

### 和网页版有什么不同

网页版是对话式的：你贴，它回，集成靠你手工完成。**Claude Code 住在你的代码所在的地方。**它读的是真实文件，跑的是真实命令，写的是真实的 commit。模型仍然跑在云端，但_工作台_是你自己的机器、你自己的终端、你自己的文件系统。

这正是「离线 AI」这个说法搞错的地方，所以我直说：

## 关于「离线」的一言

我想先坦白一件事，很多评测里我都看到过——包括我差点写反的那篇简报。**Claude Code 不是离线 AI。** CLI 跑在本地，但每条提示词和每次模型响应都要走网络到 Anthropic 的服务器。[数据使用文档](<https://code.claude.com/docs/en/data-usage>)写得很直接：「Claude Code 本地运行。要与 LLM 交互，Claude Code 通过网络发送数据。」

如果你要的是完全跑在自己机器上的模型，你在找的是别的东西——Ollama、LM Studio、本地的 llama.cpp。那是另一个品类。

Claude Code _确实_提供的东西——我觉得「把 AI 搬离线」这个标题真正想说的——是**对 AI 周边事物的本地掌控**：它看哪些文件、跑哪些命令、碰哪些第三方服务。这才是真实故事，值得不靠那种误导性简写讲清楚。

## 为什么隐私在驱动这场迁移

下面是隐私故事里诚实的那版。

### 什么数据离开你的机器，什么不会

运行 Claude Code 时，你的提示词和相关的代码上下文会经 TLS 发给 Anthropic。CLI 本身、你的完整仓库、`.claudeignore` 里的任何东西、任何你没有显式纳入会话的内容——这些都不动。边界由你决定，逐文件地决定。

这和贴进浏览器**有本质区别**：在浏览器里，你往往贴得比需要的多，因为上下文要靠你手工解释。用 CLI，上下文来自你实际指向的那些文件，不多不少。

![3.PNG](/blog/images/oh-my-codex-vs-superpowers/1777514573993-699a313a-6b40-458b-a9b4-b9223d4e765e.PNG)

### 为什么单人创业者比企业团队更在乎

2025 年 9 月，Anthropic [公布了更新后的消费者条款与隐私政策](<https://www.anthropic.com/news/updates-to-our-consumer-terms>)，改变了 Free、Pro 和 Max 账号的默认设置——_包括绑定这些账号的 Claude Code 会话_。新的或恢复的会话现在可能被用于模型训练，除非你选择退出；若选择加入，保留期五年。

这对企业影响较小——Claude for Work、API 用量、Bedrock 和 Vertex 默认仍不参与训练。对单人创始人影响更大，因为那正是我们大多数人所在的账号类型。

[Anthropic 隐私中心](<https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training>)一步步教你怎么检查设置。如果你在 Pro 或 Max 套餐上跑 Claude Code，这件事值得你下午花十分钟。

我不得不改了自己的设置。我以为我几个月前就已经退出了。其实没有。

## 纯云端 AI 的真正代价

我不会假装云端是敌人。它不是。模型需要云端算力才能跑。但一个_纯粹_基于浏览器的 AI 工作流确实有真实的代价，而这份代价没有写进任何定价页。

### 延迟、依赖与数据暴露

延迟是最明显的。浏览器 → 贴上下文 → AI 响应 → 手动复制回来 → 编辑器。这里三秒，那里四秒。在迭代东西的时候累积得飞快。

依赖是更安静的代价。你的 AI 标签页挂了、撞上速率限制、或对话中途丢了上下文，都会打断你的流程——CLI 不会这样。CLI 住在你工作所在的地方。

数据暴露是最让我在意的，在我换配置之前。每一次粘贴都是一次小小的判断：_这个安全吗？里面有没有密钥？这段注释会不会泄露上下文？_ 多数时候我判断对了。但「多数时候」不是我想用于自己数据卫生的标准。

### 为什么纯云端 AI 不一定是最优解

我想温和地反驳一件事。如果你的 AI 工作流是「开浏览器、贴、复制、贴回去」——你付的这笔税和模型质量毫无关系。**模型不是瓶颈，交接才是。**换成终端原生配置不会让 AI 更聪明，它只是移除了 AI 与你的实际工作之间的摩擦层。

我也觉得很多人悄悄高估了自己对浏览器的需求。试着一周不用它，你很快就会知道。

## 怎么在 Linux 上安装 Claude Code

好，到实用部分了。我会简短些——官方文档写得很好，没必要复述。

### 系统要求

  * Ubuntu 20.04+、Debian 10+ 或同等发行版

  * 最低 4GB 内存

  * 联网（对，还是需要——见上文）

  * 付费 Claude 账号：Pro、Max、Team、Enterprise，或 Console（API）账号

### 分步安装

原生安装器是 Anthropic 现在推荐的方案。不用 Node.js，不用 npm 那套折腾：


    curl -fsSL https://claude.ai/install.sh | bash

安装就这么多。跑完后开一个新终端，让 `PATH` 识别新二进制，然后验证：


    claude --version

如果你偏好 npm——底层是同一个二进制，只是少了自动更新——可以通过 [npm 上的官方 @anthropic-ai/claude-code 包](<https://www.npmjs.com/package/@anthropic-ai/claude-code>)安装。别用 `sudo`。文档明确说了，而且说得对；用了以后会制造权限问题。

首次启动（在任意项目目录里跑 `claude`）会带你走一遍 OAuth 或 API key 认证。**有一件事值得立刻做：**跑一下 `claude doctor`。它会检查你的安装、shell 配置和认证状态，有任何问题都会告诉你。

想尽量少开遥测，就在首次会话前设置这些：


    export DISABLE_TELEMETRY=1  
    export DISABLE_ERROR_REPORTING=1

这两个不会影响训练数据——那是另一层、按账号设置的——但它们能收紧为运营日志而离开你机器的内容。

## 本地 AI：能做什么、不能做什么

把这一节当作「什么修不了」的现实检查。

### 本地处理帮得上忙的地方

  * **文件系统边界。** Claude Code 只在启动它的那个目录内写入。它可以读外部，但写操作被限定在范围内。这是真实的安全属性。

  * **权限门控。** Bash 命令、编辑、网页抓取——首次都会弹窗征求批准，你可以把想要的加进白名单。你在事情发生之前能看到将要发生什么。

  * **`.claudeignore` 文件。**语法和 `.gitignore` 一样。里面的任何东西，Claude Code 永远不会读。你的 `.env`、密钥目录、私人笔记——按名排除它们。

  * **不是粘贴出来的上下文。**模型只看到你指向的东西，不多不少。

### 哪些地方仍然离不开云端

模型本身。推理、代码生成、多步规划——全在服务端完成。你没法飞。没有联网你就没法工作。你没法避免把提示词和相关上下文送上网线。

如果你的威胁模型真的要求什么都不离开机器——气隙环境、涉密项目、合规约束的代码——Claude Code 不是你的工具。用纯本地模型，并接受能力的取舍。

对大多数单人创始人来说，现实的问题不是「云端还是非云端」，而是「我的工作流有多少想靠自己的手拼起来，又有多少想交给一个住在工作所在之处的东西」。就这个问题而言，**从浏览器迁到终端是我一年里做过最干净利落的升级之一。**

还有一点值得提：从散落的标签页到一个统一的工作台，本身就是一条生产力叙事。HBR 2022 年的一项研究追踪了三家财富 500 强公司的 137 名员工，发现他们每天在应用之间切换约 1,200 次。单人创始人对这个数字也不免疫——只是我们更不容易去数它。

![6.png](/blog/images/oh-my-codex-vs-superpowers/1777514616142-df91b981-531f-4abc-89bc-585e073bbd4b.png)

这就是我现在对这件事的看法。「离线 AI」这个标题，为一个其实更接近「少经浏览器中转的 AI」的想法承担了太多。两码事。但无论如何都值得做——尤其如果你一整年都在往聊天窗口里贴代码、默默祈祷一切顺利。

如果你这周要试，我只会先把你推向一个地方：隐私设置页。确保你的训练 opt-in 状态正是你想要的。其余配置可以等到明天，那个不能。

## 常见问题

### Claude Code on Linux 真的离线吗？

不。CLI 跑在本地、工作在文件系统上完成，但每一次模型交互都会经网络发往 Anthropic 的服务器。如果你见过把 Claude Code 说成「离线 AI」的说法，那是错的。准确的说法是「本地执行面 + 云端模型」。

### 本地 AI 模型和云端 AI 模型有什么区别？

本地模型（Ollama、llama.cpp、LM Studio）完全跑在你的硬件上，提示词不会离开机器。代价是能力——能在本地跑的开放权重模型，通常比前沿模型落后一两步。Claude 这类云端模型跑在专用基础设施上，提供最新能力。Claude Code 是一个带本地_界面_的云端模型。不同品类。

### 配置它需要技术能力吗？

如果你会跑一条 `curl` 命令、会跟着浏览器里的 OAuth 提示走，你就能装好它。如果你只用过聊天式 AI，第一次用 CLI 会觉得陌生，但那只是几个小时的适应，不是几周。感觉哪里不对就跑 `claude doctor`——它是整套工具里最有用的命令。
