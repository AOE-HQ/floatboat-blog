最好的 Agentic AI 工具不是能做最多事的那一个，而是执行边界恰好对应你愿意交出去的那项工作。

「Agentic AI 工具」现在可以指对话中调用工具的助手、在应用之间搬运记录的定时工作流、自己选择下一步的构建平台、修改代码库的编程 Agent，以及横跨文件和连接服务的工作区 Agent。区分它们的不只是模型能力，更是它在哪里运行、能触达什么、会持续多久，以及谁来批准高后果动作。

本文不做排名。厂商文档只用来确认当前能力，功能列表不能证明可靠性。选型应从一条具体工作流、可接受的失败和恢复方案开始。

## 什么样的 AI 工具才算 Agentic

普通助手把 Prompt 变成回答。Agent 则循环执行：观察上下文、选择动作、使用工具、检查结果，再决定下一步。判断一个产品是否 Agentic，不要看官网有没有写「Agent」，而要看它能否围绕目标自主选择并执行多步。

四个变量决定真实自主度：

1. **范围：**一份文档、一个应用、一个代码库，还是多个连接系统？
2. **时长：**一轮对话、长任务、定时执行，还是事件触发？
3. **权力：**只读、起草、编辑、发送、购买、部署，还是删除？
4. **监督：**全程驾驶、关键点批准、只审异常，还是无人执行？

Anthropic 的[Agent 构建研究](https://www.anthropic.com/research/building-effective-agents)区分了 Workflow 与 Agent：前者路径由代码决定，后者由模型主导。路径已知时，确定性工作流通常更合适；输入变化大、下一步无法穷举时，Agent 的判断才有价值。

## Agentic AI 工具的五个品类

![五类 Agentic AI 工具的执行边界](/blog/images/agentic-ai-tools/tool-selection-map-zh.svg)

| 品类 | 最适合 | 通常能触达 | 主要控制 | 主要计费单位 |
|---|---|---|---|---|
| 工具型助手 | 研究、起草、分析 | 当前对话、文件、已批工具 | 用户留在对话中 | 席位或消息额度 |
| 工作流自动化 | 重复、结构化操作 | 连接应用与预设步骤 | 触发、分支、错误路由 | Task、Operation 或 Credit |
| Agent 构建平台 | 需要判断的可变流程 | 配置知识、工具、渠道 | 工具策略与评测 | Run、Action、Token 或 Credit |
| 编程 Agent | 代码库与技术操作 | 文件、终端、测试、版控 | Sandbox、批准、Code Review | 席位、额度、Credit 或 Token |
| 工作区 Agent | 跨应用长任务 | 文件、记忆、应用、日程 | Workspace 权限与 Log | 席位加用量或 Credit |

这是品类地图，不代表同一行的每个产品都一样。很多产品正在跨越品类。要比较的是你实际使用的执行入口，而不是公司 Logo。

### 工具型助手

对话助手是研究、综合、规划和起草的低摩擦选择。它擅长快速切换上下文，弱点是持续性：一次好对话不会自动变成可重复流程，能搜索或读文件也不等于适合无人发消息。

输入差异大、输出容易审阅，而且任务以文档或建议结束时，先选助手。

### 带 AI 步骤的工作流自动化

Zapier、Make 和 n8n 这类工具最适合触发条件与目标已经清楚的工作：表单到达，系统分类，创建记录，将异常交给人。AI 可以解读非结构化文字，但不必接管整条流程。

流程图让这一类更容易测试，费用却可能不直观。Zapier 计数成功执行的 Task，Agents 还会计算动作、浏览与知识查询。Make 的 [AI Agent Credit 文档](https://help.make.com/credit-usage-for-ai-agents)则分开计算 Operation、工具调用和模型 Token。循环或多工具调用会让一次看似廉价的 Run 成倍增长。

稳定、高频、输入输出明确的工作适合这一类。如果每个案例都要重新规划，或所谓流程其实是没定义清楚的业务规则，就不要急着自动化。

### 无代码与低代码 Agent 构建平台

这类平台让运营者定义角色、知识源、工具、记忆和部署渠道，适合目标稳定、路径会变的任务。

关键不是可视化画布，而是外围控制：失败 Run 能否重放？Prompt 版本能否锁定？工具调用是否可见？开发与生产凭据能否隔离？对外动作能否强制批准？指令与测试集能否导出？

任务已有足够示例可以评测时，再上 Builder。如果团队还说不清正确结果，平台只会遮住歧义。

### 编程 Agent

代码有 Diff、测试、Lint、类型检查和版本控制等反馈。Agent 可以读库、改文件、跑验证，再在开发者审查前修正 Patch。

这种权限也会带来风险。OpenAI 说明 Codex 默认在禁用网络的 Sandbox 中运行，对提权动作请求授权，但仍建议部署前人工审查。[Claude Code CLI 文档](https://docs.anthropic.com/en/docs/claude-code/cli-usage)列出 Allowed/Disallowed Tools、Turn Limit、Permission Mode，以及名称就是警告的 `--dangerously-skip-permissions`。Agent 能执行 Shell 命令时，这些控制比 Benchmark 分数更重要。

范围清晰、能回滚、有机器可检验验收条件的任务才适合。不要因为测试通过，就交出生产凭据、不可逆迁移或部署权。

### 工作区 Agent

工作区 Agent 把持续上下文、文件、工具、记忆、日程和协作放在一起，适合成本主要来自研究、文档、消息与审阅交接的工作。

OpenAI 的[工作区 Agent 文档](https://openai.com/index/introducing-workspace-agents-in-chatgpt/)列出云端运行、日程、连接应用、ChatGPT 或 Slack 共享，以及管理员通过 Compliance API 查看配置与 Run。这种广度是价值，也是治理必须先于便利的原因：跨应用 Agent 会同时继承多套权限体系。

流程确实横跨产物与应用、共享上下文应超过一次对话持续存在时，再选工作区。

## 按工作流选，不要按 Logo 选

| 工作流 | 合理起点 | 原因 | 必须保留人工的地方 |
|---|---|---|---|
| 比较来源并起草 Brief | 助手 | 输入会变，输出易审 | 来源核对与结论 |
| 分流表单并创建记录 | 工作流自动化 | 触发、字段、去向明确 | 异常与重复 |
| 用可变证据分流客服 | Agent 构建平台 | 路径会变，工具集明确 | 退款与改账户 |
| 修复仓库问题并跑测试 | 编程 Agent | 文件和测试提供反馈 | Diff、Secret、Merge、Deploy |
| 准备每周跨应用复盘 | 工作区 Agent | 需持续产物与日程 | 对外沟通与承诺 |

好的试点任务重复、有边界、可观测、可逆，而且即使最后一步仍需人批准也有价值。成功主观、样例太少、权限太广，或一次失误就会形成法律、财务或客户承诺的任务，不是好试点。

## 比较总成本，不要只看套餐首页

Agentic 工具的成本至少包含：席位与最低套餐；Task、Operation、Agent Activity 或 Credit；模型输入输出、Cache、Search、Storage 与 Computer Use；重试、循环、评测与失败 Run；付费 Connector；人工审核、事故恢复与 API 变更后的维护。

计算每个**验收通过的结果**成本，而不是每次 Run 成本。100 次运行如果只有 70 次可用，就把全部平台、用量、审核和返工成本除以 70。还要测最差合理分支：平时调两个工具的流程，缺数据时可能调十次。

计费变化很快。在试点文档里记录定价页与核对日期，不要把某个月费永久写进架构决策。

## 权限、数据与可迁移性

一个 Agent 可能同时拥有 Workspace Role、OAuth Grant、Service Account 权限、模型供应商保留规则、浏览器会话、文件系统权限和审批策略。要分开检查：

- 是只读，还能创建、发送、编辑和删除？
- 权限授给个人、Workspace，还是共享 Service Account？
- 管理员能否盘点 Agent、工具、凭据和 Run？
- Log 是否足以重建决策与工具调用？
- Prompt、文件、记忆和输出存在哪里、保留多久？
- 外部内容能否携带指令并触发另一个系统？
- 审核人能否停止 Run 并撤销凭据？

试点先给最小可行范围，用测试账户和非敏感数据。支付、身份管理、生产部署、破坏性删除与具约束力的客户沟通，保留明确人工批准。

可迁移不等于所有组件都必须开源，而是重要的运行知识不能只存在产品内部。把操作规则放进版本控制，用中性格式保存测试案例和验收标准，维护工具、Scope、Owner 与 Secret 清单，并把业务规则与厂商 Connector 配置分开。

因此，[Agentic AI 系统的自建还是购买](/zh/blog/building-agentic-ai-systems-build-or-buy)不能只比上线速度，还要计算迁移。

## 用两周试点换取证据

1. **准备 20–50 个案例。**包含普通工作、缺数据、冲突指令、重复记录和恶意或无关输入。
2. **先写验收标准。**明确必填字段、禁止动作、来源要求、完成状态和升级条件。
3. **测当前流程。**记录人工时间、经过时间、错误率和工作量。
4. **从只读或只起草开始。**发送和写入仍要批准。
5. **审查每次 Run。**记录直接接受、修改后接受、不安全尝试、工具失败与无法解释的中止。
6. **计算验收结果成本。**包含用量、审阅、返工和维护。
7. **每次只扩大一项权限。**对应失败已有控制与回滚后，再增加权力。

最后可以选择扩大、重新设计、保留为人机协作，或停止。如果试点证明这项工作应继续由人主导，它也没有失败。

## 工具短名单，本质上是控制决策

不存在通用的「最佳 Agentic AI 工具」。助手优化互动判断，工作流平台优化重复执行，构建平台增加灵活路由，编程 Agent 利用技术反馈，工作区协调横跨产物与服务的长任务。

先缩小品类，再用真正要跑的工作流比较权限粒度、可观测 Log、审批点、失败恢复、验收结果成本和可迁移性。能力让工具进入试用，控制和证据才能让它进入生产。
