**信息核对截至 2026 年 10 月 13 日。** 规格、托管价格、模型文件和许可条款都会变化，部署前请重新核对文中的 MiniMax 官方来源。

**TL;DR**
  * **MiniMax H3 是全模态视频生成模型**——一个把文本、图片、视频和音频当作同一段上下文来读的开放权重系统，一次前向就返回一段带同步立体声的成片，2026 年发布在 [Hugging Face](https://huggingface.co/MiniMaxAI/MiniMax-H3) 上。

  * 它最高生成 2K 分辨率、15 秒、24 FPS 的视频，32 kHz 立体声由同一个 diffusion transformer 原生产出，而不是后期配音。

  * 发布两个检查点：**FL2VA**（文本 / 首帧 / 尾帧转视频）和 **Ref2VA**（参考转视频，单次请求最多 9 张图、3 段视频、3 个音频）。

  * 按[官方 MiniMax 定价页](https://platform.minimax.io/docs/guides/pricing-paygo)，价格从 **2K 每秒 $0.13**、**768p 每秒 $0.08** 起。

  * 开放权重只覆盖 H3-Base：H3-Context-IR 预处理模块与 2K 重生成模块目前仍仅限 API。

## 1\. 为什么通用视频模型会改写游戏规则

视频生成这两年一直在向细分工具碎裂。文生视频用一个模型，图生视频用另一个，剪辑现有片段用第三个，动作迁移用第四个，人声、音效和音乐还得单独一条管线、最后在后期里合成。每个工具只理解你意图的一小片，于是真正的制作工作意味着把五家服务缝在一起，还要祈祷它们对「主体长什么样、镜头怎么运动、场景该是什么氛围」有一致的理解。

MiniMax H3 尝试把多种媒体放进同一套生成系统。它在 2026 年 7 月 31 日发布，基础模型权重于 8 月 3 日上架 Hugging Face。官方材料可确认的是：模型能在同一段上下文里接收文本、参考图、参考片段与音频，再生成带原生音频的视频。真正需要评估的不是未经定义的“画质排名”，而是这种统一输入方式能否减少具体工作流的工具切换，同时保持可接受的连续性、音画同步与修改成本。另一端的设计思路是高度专门化，例如 [TypeSafe 的 Jev](/zh/blog/what-is-jev-model) 只输出类型化概率决策；两者服务的任务边界不同。

这个套路对见证过 LLM 品类整合的人来说很眼熟：前沿实验室先抢跑定义品类，然后开放权重登场，生态系统——推理框架、硬件厂商、社区工作流——几天之内就跟了上来。视频生成如今正处在同一个拐点，而 H3 是第一个认真把手权重交出来、而不是锁在 API 后面的全模态模型。Kimi K3 开放前沿模型权重时我们写过类似的拆解；H3 就是那个故事的视频版。

## 2\. MiniMax H3 定义

### 2.1 核心定义

MiniMax H3 是一个通用、全模态的生成系统。它接受由文本、图片、视频和音频组成的多模态上下文，理解这些输入之间的关系，一次前向就生成带原生立体声的视频。这里的「全模态（Omni-Modal）」不是时髦词——它意味着同一个 transformer 同时预测视觉潜变量和音频潜变量，所以音轨是与画面联合生成的，而不是事后补的。

### 2.3 H3 不是什么

模型卡记录的最高输出是通过重生成路径得到 2K，并未记录 4K 路径。Ref2VA 最多接收十二个混合参考资产——图片、片段与音频——并把它们作为同一段生成上下文。因此，H3 更适合被理解为多模态生成与编辑系统：输入可以接近一份制作简报，而不只是单句画面描述。

## 3\. MiniMax H3 怎么工作

完整的 H3 系统由三个模块组成。**H3-Context-IR** 是托管的预处理与编排层，把自由形式的多模态简报转换成结构化中间表示。**H3-Base** 是开放权重生成器，根据该表示产出 768p 视听结果。**H3-Regenerate-2K** 再结合原始上下文与 768p 输出，生成官方记录的 2K 结果。公开材料解释了流程，但文字、细节、运动和音画同步仍需用自己的素材验证。

底层来看，H3-Base 是一个 330 亿参数的稠密单流 transformer，其中约 130 亿参数在自适应层归一化（AdaLN）分支里——这些分支在推理时可以预计算并缓存，[Hugging Face 模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3)里有记载。文本由构建在 Qwen3-VL-32B 完整预训练权重之上的 H3-Encoder 编码；视觉经过时间因果的 H3-VisualVAE（16× 空间、4× 时间压缩，24 个潜通道）；音频经过 H3-AudioVAE，把 32 kHz 音频压成 40 Hz 的 token 流，每个立体声通道分别编码解码。transformer 用三维多模态旋转位置编码（MM-RoPE）表示时间、高度、宽度三个维度的位置，并原生支持长序列的稀疏注意力——不过当前开放版本跑的是全注意力，稀疏注意力的实现承诺在后续更新中推出。这背后的直觉——只为真正变化的部分付全价算力——与[AI 工作里的力度控制](/zh/blog/effort-control-fast-mode-ai-work)是同一件事：按每一步的实际难度分配算力预算，而不是给每个 token 都付顶格价。

一个值得留意的设计决策是：注意力层和前馈层里没有任何模态专属的结构，所有模态专门化都在输入/输出层和 AdaLN 分支里。这就是为什么单个模型能在文生视频、首尾帧生成和十二资产参考生成之间无缝切换、无需架构级大改——也是为什么 MiniMax 能把整个东西蒸馏成任务专属检查点，每个都自带处理器、tokenizer、文本编码器、视觉 VAE 和音频 VAE。

## 4\. 如何把 H3 与其他视频模型比较

不要把厂商规格和第三方观感拼成一个“统一排名”。应使用同一组提示、参考素材、时长、分辨率和验收规则，对比你实际能访问的模型。至少记录主体连续性、指令遵从、运动、音画同步、瑕疵率、重生成次数、延迟和每条合格视频的总成本。

MiniMax 当前[官方价格页](https://platform.minimax.io/subscribe/token-plan?tab=api-enterprise)列出：H3 的 768p 输出每秒 0.08 美元，2K 每秒 0.13 美元；额外图片、输入视频、2K 重生成和 Context-IR 另有费用。这些都应计入比较，只用输出秒数乘单价会低估参考素材较多的流程。

H3 的功能摘要可以由官方模型卡直接支撑；竞品应分别查看各自最新官方文档，不再使用无统一来源的跨厂商表格。如果更大的决策是前沿能力应保持托管还是允许本地部署，可参考 [GPT-6 Astra 的部署边界](/zh/blog/gpt-6-astra)作为商业模式对照，但它不是视频质量基准。

## 5\. 「开放权重」到底开放了什么

视频生成领域的开放权重发布有信誉问题，因为过去的承诺常常最后变成「一篇博客 + 一个等候名单」。H3 的发布是真的，但是部分的——这个区别对打算本地部署的人很重要。[MiniMaxAI/MiniMax-H3 仓库](https://huggingface.co/MiniMaxAI/MiniMax-H3)里可下载的是 H3-Base 模块，分发为两个任务专属检查点（FL2VA 和 Ref2VA），各自自包含处理器、tokenizer、文本编码器、视觉 VAE 和音频 VAE。模型经由 SGLang、vLLM、diffusers 和 ComfyUI 提供服务，推荐四卡 GPU 配置；硬件兼容性从一开始就被列为设计优先项，覆盖华为昇腾、AMD、Intel 等主要芯片厂商，Hugging Face、ModelScope、ComfyUI 等推理平台也在发布当天就绪——见 [vLLM 的 H3 recipes 页](https://recipes.vllm.ai/MiniMaxAI/MiniMax-H3)。

不开源的是系统的其余部分。H3-Context-IR 是一个托管的多阶段工作流，依赖多个 MiniMax 服务，所以留在 API 后面；H3-Regenerate-2K 同样尚未发布，只提供了一个 API 用于验证官方 2K 结果。已发布检查点跑全注意力；让长上下文推理变便宜的稀疏注意力实现安排在后续更新。落到实践上：开发者可以在本地部署 H3-Base、复现 768p 结果，也可以把本地生成与 Context-IR API 组合起来逼近完整的 2K 工作流——但端到端的完整体验仍然部分受制于 MiniMax 的服务器。

许可协议是「开放」的另一半。H3 采用 MiniMax H3 社区许可发布：年营收 2,000 万美元以下的组织可免费商用，需署名；非商业使用免费——详见[官方 MiniMax H3 许可文本](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE)。这个门槛覆盖了大多数独立工作室和自由职业者，但对已融资团队是实打实的约束，所以在它之上做产品之前先读许可文本。任何开放权重模型都一样：「可下载」和「商用不受限」是两个问题。

## 6\. H3 的短板在哪

文档可确认的限制比非正式质量排名更清楚：输出时长为 4 至 15 秒，托管完整流程通过重生成达到 2K，下载的 H3-Base 并不等于完整托管系统。画面、文字、运动与音画同步应使用固定提示和参考素材测试，每条生成结果仍需经过质量检查。

本地部署 H3-Base 不能复现托管流程的全部模块。团队应分别测试下载路径与托管的 Context-IR、重生成路径，而不是假设两者输出等价。涉及对指令的理解与创意发挥，也应纳入同一套固定素材测试，而不是从演示案例推导普遍结论。

## 7\. 谁该用 MiniMax H3

H3 是否适合广告、电商、界面演示或角色参考工作，不能由模型卡直接得出。应为每类业务建立固定素材集，分别记录可读性、主体连续性、音画同步、重生成次数与人工修正时间。托管的 Context-IR 和重生成路径还应与可下载的 H3-Base 分开测试，因为两者的系统边界并不相同。

单人经营者和小型工作室应按输出时长、参考素材费用、重生成、算力与审核时间计算每条合格视频的总成本，而不是只比较一次调用价格。[MiniMax H3 Max 的实时直播](/zh/blog/minimax-h3-max-infinite-ai-livestream)讨论的是另一类工作负载，不能用来证明 H3 短片生成的质量或成本优势。

## 8\. 结语

MiniMax H3 的工具形态很明确：一套系统接收多种媒体，并生成带原生音频的视频。它是否值得采用，应由统一素材测试、完整流程成本、部署要求与许可条款决定，而不是由分辨率或价格“夺冠”的宣传决定。小团队可以先用一组固定的短片任务记录可读性、连续性、音画同步、重生成次数与人工修正时间，再决定是否扩大使用范围。

对小团队来说，务实的做法是在决定 API 或自托管之前先跑一段 5 秒测试片：按顺序检查主体一致性、镜头运动和音频，然后再加参考。如果你对更大的图景感兴趣——前沿开放权重进入主流创作工作流——我们对 Kimi K3 开放前沿模型和 vibe-coding 一条提示词游戏两篇的拆解，覆盖了这条弧线的另外两端。在 Agent 那一侧，「一个系统、统一上下文」的同一套哲学正是 agentic calendar 的驱动力——无论输出是一段视频还是一个工作周，你的上下文就是运行时。
