**TL;DR**
  * **Obsidian Vault**是存于你设备上的一个纯 Markdown 文件文件夹，Obsidian 把它打开作为个人知识库——它不是专有的云端数据库。

  * 每个 vault 可容纳笔记、附件，以及存放设置、插件与主题的 .obsidian 配置文件夹。你可以为不同的人生场景分别运行多个 vault。

  * Vault 强调**本地所有权**、**双向链接**与**开放格式**——笔记在任何文本编辑器里都能读，也能被其他工具使用。

  * Vault **不是** Notion、Apple 备忘录，本身也不是同步服务。可选的 Obsidian Sync 与 Publish 是附加项；核心应用保持免费、本地优先。

  * 想让这套本地文件夹与桌面 Agent 搭配的实践指南，见 [如何把 Obsidian 与 AI Agent 一起用](/blog/how-to-use-obsidian-with-ai-agent)。

## 1\. 为什么现在 Vault 很重要

### 1.1 知识工作需要持久归宿

多数生产力应用把笔记当作厂商数据库里的记录。这种模型在你需要离开应用、版本化文件、加密磁盘、或让另一个程序——包括 AI Agent——无需导出操作就读同一份语料之前，都还算方便。当笔记只活在登录墙和专有 schema 后面时，每上一个新工具，就多一个迁移项目。

Obsidian 押了相反的注。官方帮助材料把产品描述为本地优先的知识库：笔记以纯 Markdown 存在你的设备上，同步与发布是可选项，而不是默认的云锁定。这场押注的单位就是**vault**：一个由你掌控的文件夹，由一个懂得链接、图谱与插件的编辑器打开。

这个设计之所以历久弥新，原因被 AI 摆到了明面上。语言模型与桌面 Agent 最擅长的，是可打开、可搜索、经授权可改写的持久文本文件。vault 已经是那个形状。在把聊天插件、剪藏器或跨应用 Agent 接上笔记之前，先弄清 vault 是什么——以及不是什么——是第一步。

### 1.2 「Vault」这个词是字面意思

在 Obsidian 里，「vault」不是「加密云端」的营销比喻。它就是**磁盘上一个目录**的名字。创建或打开一个 vault，等于让 Obsidian 指向一个文件夹；创建一条笔记等于创建一个 .md 文件；搬走文件夹就等于搬走知识库；卸载 Obsidian，文件仍在。

这种字面性既是产品的核心承诺，也是多数新手困惑的来源。搜索「what is an Obsidian vault」的人往往期待一个订阅档位或一种特殊文件类型——结果他们得到的是一个文件夹。而这正是重点。

## 2\. Obsidian Vault 定义

### 2.1 核心定义

Obsidian Vault 是一个本地文件夹，装着 Markdown 笔记（及相关附件），Obsidian 应用把它当作一个知识库来对待。在应用内，你浏览、链接、搜索，并把那些文件绘成图谱；在磁盘上，它们仍是普通文件——你可以用 VS Code 打开、用 Git 提交、用你选的任何同步工具备份，或交给任何能读目录的程序。

据 [Obsidian 官方介绍页](<https://obsidian.md/help/obsidian>)，其设计核心是你拥有的纯文本、作为一等公民的链接，以及一个用插件扩展、而非单一规定流程的工具箱。vault 就是让这些原则落地成型的容器：一个文件夹、一张笔记图谱、一套与内容共存的设置。

### 2.2 五个定义性特性

**文件夹即数据库。** vault 不是隐藏的二进制存储。笔记是文件，文件夹就是文件夹。搜索、备份与迁移的工作方式和其他任何文档树一样——因为它们本来就是文档树。

**默认纯 Markdown。**排版使用开放的 Markdown 约定。你可以在 Obsidian 的实时预览或源码模式下编辑，也可以完全离开 Obsidian——语料不会丢。

**双向链接。**输入 `[[笔记名]]` 即可创建内部链接。反向链接与图谱视图能呈现文件夹表达不了的关系——这是 Obsidian 普及的联网笔记「第二大脑」模式。

**vault 级配置。**设置、社区插件、主题与快捷键都住在该 vault 内的 .obsidian 目录里。切换 vault 即干净地切换上下文；工作 vault 不必继承个人日记的插件。

**云是可选，不是强制。**核心应用不需要账号。[Obsidian Sync 与 Publish](<https://obsidian.md/pricing>) 是付费附加项，用于加密的多设备同步与公开网站。许多用户改用 iCloud、Syncthing 或 Git 同步。

### 2.3 Obsidian Vault 不是什么

边界清晰，可以避免代价高昂的工具错配。

Vault **不是 Notion**。Notion 把页面存在托管的 workspace 里，带数据库、权限与专有运行时；vault 把文件存在你的机器上。开箱即用的多人在线协作，Notion 更强；所有权与可移植性，vault 更强。

Vault **不是 Apple 备忘录或 Google Keep**。那些应用在厂商生态里优化快速记录；Obsidian Vault 优化的是能保存几十年的持久、可链接 Markdown。

Vault **不是 Obsidian Sync**。Sync 是一项可选的加密服务，能把 vault 同步到多个设备。无论你买不买 Sync，vault 都独立存在。

Vault **不是 AI 产品**。近年来 Obsidian 官方的 AI 触点主要是 Web Clipper 的 Interpreter——剪藏页面时接入你自己的模型服务商，而不是内置一个会重写你整个文库的聊天订阅。「和我的 vault 对话」这种更深度的体验，通常来自社区插件，或来自读取同一文件夹的外部桌面 Agent。

## 3\. Vault 里装着什么

用文件管理器打开一个 vault，是消除神秘感最快的方式。你通常能看到 Markdown 笔记、放图片和 PDF 的素材文件夹，以及隐藏（或可见）的 .obsidian 配置目录。新建笔记即新建文件；重命名笔记即重命名文件；在文件夹之间移动笔记是文件系统操作，Obsidian 会在侧边栏同步反映。

附件默认留在本地，除非你另有选择。这对注重隐私的人很重要：研究 PDF、客户截图、语音备忘导出，可以放在引用它们的笔记旁边，而无需上传到第三方笔记主机。这也意味着磁盘空间与备份纪律是你自己的责任——这是用所有权换来的公平代价。

高级功能仍然站在文件之上。**属性（Properties）**用 YAML frontmatter 给笔记加结构化字段——状态、客户、截止日期——其他视图可以按这些字段筛选。**画布（Canvas）**把空间布局存成开放的 .canvas JSON，让头脑风暴保持可移植。**Bases**于 2025 年作为核心插件引入，在笔记属性之上构建类似数据库的表格、卡片、列表与地图视图，而底层数据仍留在 Markdown 里。这些功能没有一项把 vault 变成封闭数据库；它们只是在开放格式上加了视图与元数据。当你之后把同一个文件夹交给脚本、Git 仓库或 AI Agent 时，这一点就很重要：Agent 看到的是文件和 frontmatter，而不是一个锁死的厂商 schema。

日常用法差异很大。有人只维护一条收件箱笔记、每周处理一次；有人用几百条原子笔记维持一张密集的 Zettelkasten（卡片盒）网。两种模式都归于同一条 vault 契约：只要你能在文件夹里找到文件，Obsidian 就能打开它，你授权的任何其他工具也能。应用的搜索、反向链接面板与书签，都是契约之上的便利——而不是你数据的第二份副本。

多 vault 很常见。顾问常把客户 vault 与个人卡片盒分开；研究人员把实验笔记与教学材料隔离。代价是上下文切换；收益是当插件、模板或分享策略不同时，能把爆炸半径控制住。一条好用的经验法则：只有当信任边界或插件栈出现分叉时才拆 vault，而不是仅仅因为主题标签看着挤。标签与文件夹可以在一个 vault 里分隔主题；独立的 vault 分隔的，是不同的世界。

## 4\. Vault 与相关概念的对比

**云端知识库（Notion、Coda、Craft）。**团队在线协同编辑、需要权限、评论与托管数据库时，这类工具更强。单人操作者（或同步文件的小团队）想要离线速度、Git 友好的历史与零格式锁定，vault 更强。许多人两者都用：Notion 放团队页面，vault 做私人思考。

**其他本地 Markdown 应用（Logseq、Foam、Typora + 文件夹）。**好几款应用共享「Markdown 文件夹」这一思路。Obsidian 的差异化在于成熟的插件生态、图谱与反向链接的 UX，以及横跨桌面与移动端的商业级打磨——而不是发明了本地文本文件。

**文件同步文件夹（Dropbox、iCloud Drive、Google Drive Desktop）。**同步客户端搬运字节，不提供链接补全、图谱视图或面向笔记的编辑器。vault 可以住在一个同步文件夹里，但同步本身不是知识库。

**读取文件夹的桌面 AI Agent。**截至 2026 年，越来越多工具把本地目录当作多步任务的工作记忆——会议简报、项目草稿、文件清理。vault 尤其适合这种模式的目录，因为笔记本身就是文本、彼此链接且经过人工整理。这种搭配是工作流选择，不是 Obsidian 必须自己实现的功能；我们在配套指南 [把 Obsidian 与 AI Agent 一起用](/blog/how-to-use-obsidian-with-ai-agent) 里走了一遍实际配置。

## 5\. 谁该用 Vault——谁不该

Vault 适合看重**长期所有权**的操作者：作家、研究者、顾问，以及预期自己的知识库会活过任何单一应用订阅期的单人创始人。它也适合那些本来就用文件夹和 Markdown 思考的人，或希望重要写作有 Git 历史的人。如果你曾因某款 SaaS 关停而失去多年的笔记，vault 模型的吸引力既是情感上的、也是技术上的——它的失败模式是「我仍然留着那个文件夹」，而不是「但愿导出还管用」。

当你的主要需求是**与永远不会安装 Obsidian 的访客做实时多人协同编辑**、或你不愿做任何本地文件管理、想把一切都放在单一 SaaS 登录后面时，vault 作为默认方案就比较弱。移动端在 iOS 与 Android 上可以记录，但大型语料的繁重 vault 维护，在桌面上做起来仍然最自然。公开分享可以通过 Obsidian Publish 或导出选定笔记实现——但那是刻意为之的发布步骤，不是 Notion 用户习惯的默认协作面。

上手摩擦是真实的。链接、插件与模板可能在头一周就把人压垮。解药是把范围做小：一个 vault、每日笔记、少量项目页，只在两个想法确实彼此需要时才建立链接。「功能观光」——还没养成写作习惯就装二十个社区插件——是人们放弃一个本可用得很好的 vault 的最常见原因。

就这个品类而言，定价形态出奇清晰：[Obsidian 核心应用](<https://obsidian.md/>) 截至 2026 年对个人与商业使用都免费；只有当你想要官方 Sync、Publish、Catalyst 抢先体验或可选的商业支持许可时才付费。这意味着「试试 vault」几乎没有财务门槛——剩下的只有学习曲线：把笔记彼此链接，而不是把它们一股脑倒进一个无限滚动的页面。

## 6\. 本地知识库的下一步

本地 Markdown 不再是针对云文档的小众抗议。它正在成为人类记笔记与机器执行之间的交换格式。Obsidian 2025–2026 年的路线图扩展了 Bases、Web Clipper 工具、CLI 自动化与无头同步客户端——这些基础设施让 vault 在不放弃纯文本的前提下更容易被查询与操作。

市场的分裂看起来会持续：一边是托管的协作工作区，一边是本地优先的个人知识图谱，Agent 与剪藏器架在两者之间做桥。Vault 不会取代 Slack 或共享的 Notion wiki。它们仍是思考累积的个人层——而且越来越成为这样的文件夹：当你想让 Agent 在你已信任的笔记上干活时，就允许它去读。

## 结语

Obsidian Vault 说穿了就是一个 Markdown 笔记文件夹，Obsidian 把它打开成彼此链接的知识库。它的力量刻意地朴实：开放格式、本地控制、在你已理解的文件之上做链接与图谱。它不是云工作区、不是同步套餐、也不是 AI 订阅——它是笔记的持久归宿，让其他工具（包括 AI Agent）可以在你的磁盘上与之相遇。

如果你要的是定义，那就建一个 vault，把应用旁边的文件夹打开看看。如果你要的是下一步——不只在 Obsidian 里、而是把那些笔记用进日历、邮件与项目文件——请继续阅读上面链接的教程。
