Claude Tag 是 Anthropic 面向 Slack 的共享 Agent 入口。组织给 Claude 开放指定频道与连接工具后，频道成员可以提及 `@Claude` 委派工作，任务讨论和结果留在团队原本协作的地方。

**信息核对截至 2026 年 10 月 13 日。**Claude Tag 于 2026 年 6 月 23 日发布，并取代此前的 Claude in Slack 应用。接入范围、支持工具和管理员设置会因套餐与组织而变化。

## Claude Tag 到底是什么

Anthropic 的[官方发布公告](https://www.anthropic.com/news/introducing-claude-tag)把 Tag 描述为 Slack 中的团队成员。Claude 可以使用获准频道里的相关信息，连接指定工具、数据和代码库，并规划之后要完成的任务。

它最关键的特征是共享上下文。私人聊天只知道一个用户提供的材料；Tag 可以进入多人共同补充需求、纠错和决策的频道。团队不必把每次提示复制到另一款应用，也能看见 Agent 接到了什么工作。

## 一项 Tag 任务怎样进行

1. 管理员或授权用户开放指定频道与工具；
2. 频道成员用 `@Claude` 说明任务和期望结果；
3. Claude 结合可见频道上下文与连接系统规划或执行；
4. 团队在同一空间补充约束、回答问题并复核；
5. 后续工作继续附着在频道记录上，而不是某个人的私聊中。

任务可以涉及调研、指标、支持问题、缺陷分析或代码工作。具体能力取决于连接工具和权限；加入 Slack 本身不会让 Claude 自动获得所有公司系统。

## Tag 不是 Slack 搜索，也不等于 Slack AI

搜索助手负责找消息或总结讨论；Tag 的目标是委派。它可以把频道上下文作为多步任务的输入，并在连接工具里继续工作。搜索只是其中可能的一步。

Tag 也不会把每条 Slack 消息都当成指令。团队通过 `@Claude` 明确触发，并选择允许访问的频道。即便如此，组织仍应规定什么任务可以交给 Agent。

## Tag、Cowork 与 Claude Code 的边界

任务属于团队，而且 Slack 讨论本身就是证据时，用 **Tag**；一个负责人需要文档、表格或跨应用成果时，用 **Cowork**；代码仓、测试和工程审查定义完成时，用 **Claude Code**。

完整判断矩阵见[Claude Code、Cowork 与 Tag 对比](/zh/blog/claude-code-vs-cowork-vs-tag)。如果频道原生协作方向正确、但 Claude Tag 不合适，可继续看[Claude Tag 替代方案](/zh/blog/best-claude-tag-alternatives)。

## 哪些工作适合 Claude Tag

Tag 更适合上下文本来就分散在多人讨论中的任务，例如调查频道中反复出现的支持问题、汇总指标并向同一批利益相关者解释变化、协调产品与工程的缺陷排查、把长决策串整理成有人负责的行动计划，或根据频道证据与连接系统生成状态更新。

如果源数据不应被频道成员看见、已有确定性工作流稳定运行，或没有人负责最终决定，Tag 就不合适。共享可见能改善协作，但不能替代责任人。

## 权限与记忆必须有边界

选择频道本身就是安全决策。只开放完成职责所需的频道，并检查连接工具会不会暴露超出频道成员权限的信息。能够读取数据源，不代表可以把所有内容贴回 Slack。

发送消息、修改记录、合并代码或公开发布等动作应设置审批。团队还要知道频道上下文如何保留、怎样撤销访问，以及去哪里审查操作记录。

记忆适合保存决定与偏好，却不能把过时讨论自动升级为当前政策。重要规则应放在权威文档或系统中，而不是只存在于积累的频道聊天里。

## 怎样做一个可靠试点

先在一个非敏感频道测试只读为主的任务。明确交付物，并要求引用对应消息或连接记录。除了正常案例，还要测试模糊请求和权限失败。

重点观察正确的人能否跟上过程、私人信息是否留在范围内、人工需要纠正多少，以及频道是变得更清楚还是更嘈杂。只有团队能复核和恢复错误后，才增加写权限。

## 结论

Claude Tag 把 Slack 变成团队委派工作的共享入口。它的价值不只是 Claude 能在频道回答，而是团队能够共同提供上下文、看见交接，并沿同一份记录继续工作。

这项价值依赖清晰的频道范围、工具权限、审批规则和任务负责人。只有协作本身属于任务时，Tag 才比“把聊天机器人放进 Slack”更有意义。
