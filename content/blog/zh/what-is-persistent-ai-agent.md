持久化 AI Agent 可以在一轮对话结束、进程重启或等待人工审批之后继续工作，但这不是因为模型天然拥有永久记忆，而是模型外部的系统保存并恢复了必要状态。

「Agent 记得」可能指完全不同的事情：它能重读当前对话、恢复一条做到一半的流程、找回上个月记录的偏好，或者查询客户系统里的最新资料。每一种能力都需要不同的存储、权限、保留期限与测试。把它们统称为「记忆」，系统会显得很方便，直到它引用了错误事实，或把一个有后果的动作执行了两次。

本文把这些层次拆开，并给出一套可检查的架构、权限与评估方法。

## 持久化 AI Agent 的准确定义

持久化 AI Agent，是指获准保存的状态能够跨越一次模型调用，并在后续步骤、运行或会话中恢复的 Agent。它通常具备三项特征：

1. **身份可延续：**系统能把下一次请求关联到正确的用户、租户、项目、任务或流程。
2. **状态可恢复：**经过选择的信息存放在模型上下文之外，中断后仍能取回。
3. **继续运行受控：**系统知道什么可以自动恢复、什么必须重新计算、什么必须再次请人批准。

持久化不等于什么都记得，也不代表 Agent 会从每次交互中正确学习，更不代表任务可以无限运行。合理的设计只保存有明确用途、责任人、有效期和删除路径的信息。

## 经常被混成「记忆」的七个概念

### 1. 会话上下文

会话上下文是一次对话或短期会话中可供模型使用的消息与工具历史。它让「用第二个方案」这样的指代能够被理解。上下文窗口快满时，应用可能裁剪、摘要或检索更早的内容。

这能维持连续性，但不一定构成长时持久化。摘要会漏掉细节；上下文窗口更长，也不意味着其中每一条事实都会被正确使用。

### 2. 运行状态

运行状态记录某一次执行正在做什么：当前步骤、输入、工具结果、重试、审批、错误与待执行动作。它的用途是让流程能够安全暂停与恢复。

LangGraph 官方文档把节点边界的检查点、中断时保存状态与故障恢复写成明确机制；Temporal 所说的持久执行，则强调在进程崩溃、网络超时或长期等待之后恢复。这些属于执行保证，不是个人偏好记忆。

### 3. 持久记忆

持久记忆保存经过选择的跨会话信息，例如用户偏好、项目决定或长期约束。记忆服务可能从交互里抽取、合并这些记录。AWS AgentCore 就把单次会话内的短期内容，与保存关键洞察的长期记录分开。

由于抽取依赖模型或规则，记忆可能不完整、过期、归错人，或者把一次例外过度概括成长期偏好。它应当带来源、时间与可信度，而不是被当成不可质疑的事实。

### 4. 检索

检索是在请求发生时查找相关材料：旧对话、文档、数据库记录或记忆条目。检索不代表 Agent 已经「学会」这些内容；它只是对存量资料发起查询，质量取决于索引、过滤、权限、排序与新鲜度。

持久化系统通常需要同时使用语义相似度和结构化边界，例如租户、项目、记录类型与生效日期。只靠语义相似，很容易召回一条看似相关、实际无权访问或已经失效的记录。

### 5. 长期任务

持续数小时或数天的任务，需要持久检查点、截止时间、幂等键、工具回执与审批状态，但未必需要个人记忆。发票审批流程可以在经理回复后继续，而不必把经理的偏好存到未来所有对话里。

### 6. 学习

学习意味着根据证据改变未来行为。保存聊天记录不是学习；保存一条模型生成的「经验」也不等于经过验证的学习。

可用于运营的学习需要审查闭环：提出规则或可复用步骤，用样例测试，批准并发布一个版本，监测效果，质量下降时能够回滚。让 Agent 悄悄改写自己的指令，只会把一次错误变成长期错误。

### 7. 系统事实源

系统事实源负责提供当前权威事实：CRM 里的客户状态、工单系统里的负责人、日历里的会议、代码仓库里的发布版本。Agent 记忆不能覆盖它。

如果记忆写着合同 6 月到期，而合同系统显示 8 月，当前权威记录必须优先。记忆可以保留上下文——「客户曾询问旧的 6 月日期」——但不应自己升级成事实源。

## ChatGPT 和 Claude 并非简单的「无状态」

声称主流 AI 助手每次新对话都会忘掉一切，已经不符合当前产品事实。

OpenAI 最新的 ChatGPT Memory 说明显示，可用能力可能包括已保存记忆、引用聊天历史、自定义指令、文件和连接应用内容；具体能力会随套餐、地区、平台与工作区设置变化。官方也明确说明，Memory 不会保留每个细节，已保存记忆可以与聊天历史分开存在，仅删除原对话不一定会删除相应记忆。

Claude 当前的官方帮助文档也说明了历史对话搜索与记忆，并提供套餐、组织、项目边界以及编辑、删除、无痕或关闭记忆等控制；具体可用性同样取决于产品环境。

这些功能可以支持跨会话个性化与检索，但不会自动提供业务流程恢复、外部动作不重复执行、权威数据更新或完整审计。产品记忆与持久化 Agent 编排有交集，却不是同一个问题。

## 一套可落地的持久化架构

生产系统可以拆成六个互相配合的层：

| 层 | 保存或负责什么 | 核心要求 |
|---|---|---|
| 身份与范围 | 用户、租户、项目、角色 | 不能跨错边界检索 |
| 对话存储 | 消息与附件 | 保留、导出、删除、访问控制 |
| 工作流状态 | 步骤、检查点、审批、重试、回执 | 安全恢复与外部动作幂等 |
| 记忆存储 | 筛选后的事实、偏好、经历 | 来源、过期、纠正、可信度 |
| 知识与事实源 | 文档和实时业务数据 | 新鲜度与权威优先级 |
| 评测与审计 | 轨迹、版本、结果、事故 | 脱敏、权限、可重复测试 |

每次调用模型时，上下文组装器只放入当前需要的内容：现行指令、有限的近期对话、相关且获准使用的记忆、检索到的来源，以及事实源中的实时数据。模型提出回答或工具动作；策略层检查授权，并在必要时要求审批；工作流引擎记录结果与新检查点。

写入记忆应当是单独的决定。不是每条消息都值得长期保存。写入策略至少要规定类别、来源、责任人、敏感级别、保留期限与冲突处理规则。

## 权限、保留和删除本身就是功能

持久化既提高 Agent 的价值，也放大访问控制出错的后果。

### 每次读写都要限定范围

使用稳定的租户、用户、项目、任务与记忆命名空间标识。在检索之前完成授权，而不是让模型看见结果后再过滤。读取工具与写入工具分开授权，范围越小越好。

不要把提示词里写着的项目名称当成权限边界。权限必须由应用和存储层执行。

### 按数据类型规定保留期限

对话日志、工作流检查点、个人偏好、业务事实与审计记录需要不同生命周期。「以后也许有用，所以永久保存」不是保留政策。

每一类数据都应记录保存目的、默认到期时间、法律或合同要求、归档规则，以及谁有权修改。已完成流程的短期状态往往可以较快过期；偏好可以保留到被修改；受监管的审计证据则按另一套时间表管理。

### 删除必须完整而且能验证

删除一段对话，未必会同时删除由它生成的记忆、向量、导出文件、备份、轨迹或连接系统里的副本。完整的删除流程应找到来源与派生物，禁止未来检索，记录处理结果，并说明依法保留的部分。

可以用一条测试记录验证：创建它，等待它传播到各层，走正式删除路径，再确认搜索、记忆检索、导出和普通回答都不会重新出现它。

## 怎样评估持久化 Agent

评估不能只看「记得准不准」，还要看「该不记时能不能克制」。一个能召回所有相关信息、同时泄露私密或过期资料的系统，不是好记忆。

建立有版本的测试集，至少覆盖：

- 跨会话正确召回；
- 拒绝召回其他用户或项目的数据；
- 记忆与当前事实源冲突；
- 修改过期偏好；
- 删除与到期；
- 语义相似但不相关的记忆；
- 外部动作执行前后分别发生中断；
- 同一事件重复投递；
- 模型、工作进程或网络失败后的恢复；
- 历史记录或检索文档中的恶意指令。

衡量检索精度、有来源回答比例、过期记忆率、跨边界泄露、重复副作用、恢复成功率、无谓升级、删除完成率、延迟与成本。检查完整轨迹：取回了什么、排除了什么、运行哪个版本、工具动作为什么被允许。

## 哪些场景值得做持久化

当工作确实会跨会话或需要等待时，持久化才值得承担复杂度：

- 等待资料与多级审批的案件处理 Agent；
- 持续几天、保留逐项来源和决策记录的调研 Agent；
- 遇到限流后恢复、同时避免重复写入的运营 Agent；
- 记住已批准规范与项目决定的项目助手；
- 在账户边界内检索历史工单的客服 Agent。

一次性的敏感问题、简单确定性转换、旧上下文可能比遗忘更危险的任务，以及无法可靠识别用户和执行删除的环境，都不适合持久化。此时，无状态会话或临时模式是一项安全能力，不是缺陷。

## 上线前检查清单

1. 哪些状态需要跨越一轮对话、一次会话、进程重启和版本部署？
2. 每类事实由哪个系统提供权威版本？
3. 哪些标识和策略防止跨用户、跨项目检索？
4. 什么可以自动写入，什么必须经人复核？
5. 冲突、纠错、过期和删除分别如何处理？
6. 暂停的任务能否恢复而不重复外部动作？
7. 用户和管理员能否查看、导出与移除数据？
8. 评测是否同时覆盖召回、克制与故障恢复？
9. 存储、模型或工具不可用时，系统如何降级？
10. 错误或过期记忆造成事故时，由谁负责？

## 结论

持久化 AI Agent 不是一个拥有无限记忆的模型，而是一套围绕模型，有意识地保存、检索、恢复、纠正、到期和删除信息的有状态系统。

真正重要的设计选择，不是让 Agent 记住多少，而是系统能否区分：对话上下文与执行状态、记忆与检索、经过验证的流程与未经复核的猜测、历史背景与当前事实源。

边界清楚时，持久化能够减少反复交代，并支持真正的长期任务。边界不清时，它只是让错误活得更久。
